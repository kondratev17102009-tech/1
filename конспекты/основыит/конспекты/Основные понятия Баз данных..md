
###### **Данные** 
это информация представленная в определённом виде. Может быть в хаотичном или у порядочном формате.  

###### **База данных (БД)** 
это совокупность данных организованных по определённым правилам.
Предусматривает хранение, описание, манипулирование и удаление данных.

###### **Система управления базы данных (СУБД)**
это целый комплекс программ позволяющий манипулировать данными.

**СУБД:**

- **MySQL**

- **Microsoft SQL Server(MS SQL Server

- **Oracle**

- **PostgreSQL**

- **MongoDB**

**SQL** - язык запросов, это специализированный язык предназначенный для работы  СУБД.


###### **Особенности SQL:**

1. Не является самостоятельным языком программирования.
2. Имеет чёткую структуру, близок к естественному английскому языку.
3. Имеет декларативный характер. При написании кода, пользователь указывает, что хочет получить, а система сома определяет, как выполнить задачу.
4. В нём нет циклов, ветвей и других привычных процедурных конструкций.

###### **Список диалектов SQL:**

1. T-SQL (TransactSQL) - используется в MS SQL Server.
2. PS/SQL (Procedural Language/SQL) - используется в Oracle.
3. SQL/PSM - используется в MySQL.
4. PLpg/SQL - используется в PostgreSQL.
5. Jet/SQL - используется в Microsoft Access.

###### **Технологии в БД:**

Централизованная архитектура - когда всё на одном ПК(1 человек выполняет всю работу).

**Преимущества:**
- Легко управлять, всё в одном месте.
- Максимум безопасность.

**Недостатки:**
- Колоссальная нагрузка на ПК.
- Если сломается ПК.

###### **Архитектура файл сервер:**

Учувствуют персональные ПК и выделенный сервер на котором будут храниться файлы. 
Сервер не учувствует в обработке своих данных, они только хранит их. (если человек будет менять файл в общей папке или хранилище, человек который последний заходил вводит изменение будет приимущество)

**Преимущества:**
- Дёшево и просто настроить.
- Каждый использует свою мощность ПК для вычесления.

**Недостатки:**
- Огромный трафик нагрузка на сеть.
- Конфликт пользователей в одновременное использование.

![[Диаграмма без названия.drawio.png]]

###### **Архитектура клиент сервер:**

Одновременно можно менять разны элементы в общем хранилища без конфликта.

**Преимущества:**
- Малая нагрузка на сеть.
- Масштабируемость.
- Централизованное управление.
- Повышенная безопасность.
- Эффективная совместная работа.

**Недостатки:**
- Зависимость от сервера. 
- Зависимость от сити.
- Задержка из-за удалённого сервера.

###### **Трёх звеная Архитектура:**

**Преимущества:**
- Гибкость 
- Масштабируемость. 
- Снижение требований к ПК клиентам. 
- Повышенная отказа устойчивасть.

**Недостатки:**
- Очень сложная разработка.
- Задержка ответа по сити.
- Большие затраты на обслуживание.
